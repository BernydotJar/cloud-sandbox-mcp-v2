# Bridge Glass Toast — native macOS connection confirmation

## Purpose

Replace noisy **application-owned success messaging** with a single, understated,
non-blocking confirmation when the **dedicated Chrome CDP provider** becomes
available through Cloud Sandbox MCP V2.

**Important distinction:** Chrome itself may display a remote-debugging /
automation infobar. That is browser-controlled security UI, not a notification
generated by this project. This release **does not suppress browser security
indicators**, change Chrome policies, use deprecated `--disable-infobars`, or
disable Chrome debugging consent. A custom toast cannot safely remove Chrome's
native infobar.

## User experience

- A native macOS glass-effect floating card appears at the top-right:
  **"Bridge listo ✨"**, with the subtext **"Chrome conectado · Playwright"**.
- It dismisses automatically after 2.1 seconds, with short 220/240 ms fades.
- It uses a transparent, click-through, non-activating NSPanel: no keyboard
  focus, no buttons, no interruption to the current app or browser session.
- It adapts to the current system appearance, uses system fonts/SF Symbol,
  and respects the Reduce Motion accessibility setting.
- It appears **at most once per live Mac Bridge service process**, only when
  `browser_tabs(chrome)` successfully connects to the exact dedicated
  `127.0.0.1:9223` persistent CDP endpoint and
  `COMPUTER_USE_BRIDGE_TOAST=true`.
- It does not inject HTML or scripts into Suno, CapCut, n8n or any other site.
- Real errors continue to surface via the existing MCP results and audit logs.

## Delivery

Files: `bridge-toast.swift` (AppKit NSPanel), `upgrade-toast.mjs` (additive
code migration), `install-on-mac.mjs` (guarded Mac deployment),
`upgrade-toast.node-test.mjs` (regression checks).

The candidate release is published under:

`$HOME/.cloud-sandbox-mcp-data/shared-auth/deployment/handoff/cloud-sandbox-computer-use/bridge-glass-toast/`

From the **Mac Terminal**, while no delegated Computer Use task session is active:

```sh
node "$HOME/.cloud-sandbox-mcp-data/shared-auth/deployment/handoff/cloud-sandbox-computer-use/bridge-glass-toast/install-on-mac.mjs" --activate
```

The Mac's installed `swiftc` toolchain compiles the AppKit executable.
The installer verifies and backs up the existing Bridge source and .env,
applies only a compatibility-checked code patch and
`COMPUTER_USE_BRIDGE_TOAST=true`, and installs the binary at:

`~/Library/Application Support/LCH/CloudSandboxComputerUse/ux/bridge-toast`

It restarts only the dedicated Mac Bridge LaunchAgent. It verifies Browser
Runtime health and automatically rolls back code, config and the prior toast
binary on failure. It **never closes Chrome, transfers cookies, restarts the
Docker controller, or changes the Chrome debugging security UI**.

A safe dry-run is available with `--inspect`.

## Acceptance

1. Installer reports `ACTIVATED=PASS` and `BRIDGE_HEALTH=PASS`.
2. Cloud Sandbox `browser_runtime_status` reports persistent Chrome routing.
3. The first `browser_tabs({browser:"chrome"})` after bridge restart returns
   `provider=persistent`, while a small macOS confirmation appears and
   disappears without input.
4. A second `browser_tabs` call does **not** show a second confirmation.
5. Browser inspection and permitted actions still work, with unchanged
   authentication and audit behavior.
6. Chrome's own security indicators, where present, remain separate.

The Linux unit tests validate the source migration and event wiring. They
**do not** demonstrate the native AppKit rendering on the actual Mac; that
requires step 3.

## Rollback

Restore the backed-up Bridge file, Compose `.env`, and prior optional toast
binary from the reported backup directory, then kickstart the original
LaunchAgent. Do not delete the dedicated Chrome profile.
